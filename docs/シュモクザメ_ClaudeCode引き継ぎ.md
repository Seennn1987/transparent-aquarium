# シロシュモクザメ透明標本 Claude Code への引き継ぎ

- DATE: 2026-10-14
- 前の担当: Claude デスクトップアプリ（Mac 上の Linux 仮想環境で CT を処理し、Blender は MCP で操作していた）
- この文書の役割: Claude Code が最初に読む文書。いまの状態、決まったこと、最初に片付けること、次の作業を書く
- 経緯の正: `docs/シュモクザメ透明標本_計画書_v1.0.md`（以下「計画書」）。決定の言葉と測った数は、計画書の記録が正

ゴールは、白いスタジオで、蓋のない低い円柱の器の液の中をシロシュモクザメの透明標本が回遊し、透けた体の中まで観察できる状態にすること。イカやカメレオンと同じギャラリーに並べる。

## 3. 最初に片付けること

形の作業に入る前に、次を順に終える。どれも描写を変えない作業。

### 3.1 いまの状態をコミットする

1. 別のチャットやエディタが、このリポジトリを編集していないことをプロデューサーに確かめる
2. シュモクザメの未コミットのファイルを、1 つのコミットにまとめる。`blender/ct_hammerhead/mesh/` は `.gitignore` 済み
3. カメレオンの変更（`blender/ct_body_pipeline/skinbody.py`、`diag_excess.py`）は、カメレオンの担当のものなので、このコミットに混ぜない

### 3.2 中間ファイルを確かめる

CT 処理の中間ファイル（`zyg_clean.npy`、`skel_lab.npy`、`derolled7.npy`、`a4_skel_field.npy`、`a5_S.npy`、`pect_posed.npz`、`a7_jaw_fine.npz` など）は、前の担当の Linux 仮想環境の中にあり、10-14 の時点で Mac のフォルダには無かった。

- `blender/ct_hammerhead/work/` にあれば、それを使う（プロデューサーが前のチャットにコピーを頼んだ）
- 無ければ、3.4 で元の zip から作り直す

### 3.3 環境を作る

1. `.venv` を作る（`CLAUDE.md` のコマンド）
2. Blender で `-b -P` が動くか、短いスクリプトで確かめる。前の担当は、開いている Blender に MCP で送っていた（`a4f_render_outline.py` などは「開いている Blender に別のシーンを作る」作り）。裏で動かすときに同じ絵になるかを 1 枚で比べる
3. 前の担当の仮想環境はメモリが約 4 GB で、体積を体の範囲に切ってから処理していた（README の注意）。Mac で同じ制限が要るかは確かめていない

### 3.4 元の zip から glb まで通して作り直せるようにする

計画書 第 5 節は、最後に「最初から通しで作り直せる」ことを 1 回確かめると決めていた。まだ確かめていない。スクリプトを読んで、次の切れ目を見つけた。

| 切れ目 | 中身 |
|---|---|
| 読み込むファイル名が違う | `a7_probe.py` などが `a4_final_volume.py`、`a4_mesh.py`、`a4_headwidth_opts.py`、`pelvic_opts.py` を `exec` で読む。リポジトリにあるのは `a4c_final_volume.py`、`a4e_mesh.py`、`a4h_headwidth_options.py`、`a3e_pelvic_options.py`。仮想環境の作業フォルダでは別の名前で置かれていたとみられる（推定） |
| 作るスクリプトが見つからない中間ファイル | `c833_uvz.npy`・`c833_split.npy`（README は「処理は計画書 第 9 節」とだけ書く）、`a4_pect_R.npz`、`a4_pelv_R.npz`、`a7_uin.npy`、`a7_slit.npy`、`derolled_mips.npy`。読み込みはあるが、保存する行が見つからなかった |
| 作業フォルダの場所がばらばら | 相対パス（カレントフォルダ）、`ROOT = "/Users/shoui/..."`、`os.path.expanduser('~/mnt/transparent-aquarium/...')`（仮想環境のパスで、Mac には無い）が混ざる |
| README の順番 | 33 と 34・35 の順が入れ替わっている。A7 のスクリプトが載っていない |

次の順に直す。

1. 中間ファイルの置き場を `blender/ct_hammerhead/work/` に統一する（スクリプトの先頭で 1 か所から読む）
2. 足りない処理を、計画書の文章と残っている出力（`docs/hammerhead_ct/*.json`）から書き起こす
3. `blender/ct_hammerhead/run_all.sh`（名前は任意）で、zip から `specimen_hammerhead.glb` まで順に実行できるようにする
4. 作り直した glb と、いまの glb を比べる。組織ごとの面の数、外接の箱、`hammerhead.html` を 3 方向（`view=top`、`side`、展示の姿勢）で撮った画像の差。差が出たら、どの段で出たかを突き止めてから直す

作り直した形が、プロデューサーが了承した形と変わってはいけない。変わったら、その差の図を見せて聞く。

### 3.5 実際の画面を撮る道具を作る

前の担当の確認画像の一部は、ブラウザではなく Python で描いた絵だった。今後の見比べは、実際の `hammerhead.html` を撮った画像で行う。

- `tools/record-specimen/record.mjs` はイカの瓶のページ用で、Playwright と Mac の Chrome（`CHROME_CHANNEL`）を使う。同じ作りで、`hammerhead.html` を 3 方向、決まった大きさで撮る小さな道具を作る
- 撮った画像を、参考写真・前の版と同じ向きで 1 枚に並べる処理も一緒に作る

## 4. 次の作業

計画書 第 4 節の段と出口のとおりに進める。ここには、計画書に無い注意だけを書く。

### A7 顎・歯・エラの骨を仕上げる

1. 前のチャットの A7 の作業がどこまで決まったかを、プロデューサーに確かめる（口の開きの角度、エラの骨の形）。決まったことを計画書 第 9 節に「A7」として記録する
2. 計画書の修正手順（第 9 節の最後の節）のうち、4 と 5 が残っている。標本ページの部品を、頭骨（濃い青緑）、顎（軟骨の青）、歯（骨の赤）、エラの骨（目標 0.50 / 0.73 / 0.83）に分ける。横・下・斜めの静止画を、市販の骨格模型の写真と同じ向きで並べて見せる
3. 交尾器（雄だけにある）は、個体の性別を CT の腹びれの所で確かめてから決める

### A8 生々しさ

既にあるつまみ（まだら、左右差、内容物）から入る。乱数の種は固定する。皮歯（うろこ）は形を作らず、表面の質感として扱う案が計画書にある。

### B 動かす

- B1 の骨組みでは、椎骨を 1 個ずつの部品に分ける必要がある。CT の椎骨の境目は 101〜1010 mm に 189 区間見つかっている（`vert_bounds.npy`）。長すぎる区間 10 か所と、1010 mm より後ろは数えられていない（計画書 第 9 節 A3 の最後）
- 骨組み（アーマチュア）は、背骨の中心線と椎骨の境目から、スクリプトで作る。CT から形が決まった部品（頭、ひれ、膜）は、その骨組みに載せる
- 膜の頂点の持ち主の骨は、重みの和やいちばん近い骨で決めない。体積で切り分けたときの持ち主にし、面を減らしてから重みを付ける（カメレオンで面が伸びた失敗）
- 動きを付けたら、止めた所と動きの山を色違いで重ね、上から見て動いて見えるかを確かめる
- B2 の泳ぎの数（尾の振れの周期と振れ幅、体を伝わる波の速さ、曲がりの半径）は出典を付けて表にする。見つからない数は、案の動画か絵を見せてから仮の値を決める
- B5 の鰓と心臓の回数は、出典がまだ無い（計画書 8.5）

### C 器に入れる

計画書 第 4 節の C1〜C5 のとおり。始める前に、ギャラリーが台ごとに中身と器を変えられるかを確かめる（今は同じ標本を全部の瓶に出している）。この仕組みを変えるときは、イカとカメレオンの見た目が変わらないことを、変える前と後の画像で確かめる。

### テスト

`npm test` にシュモクザメのテストが無い。B5 の内臓の時計（間隔、一時停止で不変、強さ 0 で停止）と、C2 の回遊（1 周の間、体のどこも壁・液面・底に触れない）は、作るときに `水槽/scenes/specimen/tests/` に足し、`package.json` の `test` に加える。

## 5. プロデューサーに確かめること

決める前に、どれも案ごとの絵を並べて見せる。

| 項目 | いつ |
|---|---|
| 別の作業が同じリポジトリを編集していないか | 3.1 の前 |
| A7 で決まったこと（口の開き、エラの骨の形） | A7 の最初 |
| 色を胚の二重染色から借りる方針でよいか | A7 の部品の色を決める前 |
| エラの骨の参考図（CC BY-NC 4.0）を使ってよいか。作品を商用で公開する予定があるか | 公開の前。分かれば早いほうがよい |
| 動かす段で、椎骨を CT の形のまま使うか、CT の境目と太さから椎骨をスクリプトで作り直すか | B1 の前。両方の見本を 1 枚に並べて見せる |

最後の項目の背景を書く。カメレオンでは、CT の形を保存の変形ごと直していく作業で直しが重なった。椎骨は同じ形が並ぶ部品なので、CT で測った長さと太さからスクリプトで作れば、動かすときに部品の境目がそろう。ただし、骨格はすでに CT の形で了承されているので、どちらにするかはプロデューサーが見本を見て決める。
