# イカ水槽遊泳 計画書 v1.0

- APPROVED: 未（承認待ち）
- APPROVER: プロデューサー
- DATE: 2026-09-24
- SCOPE: Blender で作った透明標本イカ（形・骨組み・4つの動き）を、水槽（`水槽/scenes/riverscape`）に入れてブラウザ上で自由に泳がせる
- CHANGE_ID: SQUID-TANK-001
- 前提: `docs/イカ遊泳アニメーション計画書_v1.0.md`（SQUID-ANIM-001）で作った動き（ホバリング・前進・後退・ジェット噴射）を使う

---

## 1. 目的
今は水槽（水草・流木・岩・水・光）だけが動いていて、生き物がいない（元の魚は `?fish=1` を付けた時だけ表示）。
ここに透明標本イカを1匹入れ、**水槽の中を自分で考えて泳ぎ回る**状態にする。

## 2. 体験（見た目・動き）
- 水槽を開くと、イカが水草の上の開けた水中に浮いている
- しばらくホバリング（エンペラを波打たせ、腕をゆらゆら）→ 別の場所へ頭を先にゆっくり泳ぐ → 着いたらまたホバリング
- ときどき少しだけ後ろへ下がる（イカは後ろにも泳げる）
- 手（マウスのポインタ）を速く近づけると、ジェット噴射で尾を先に急発進して逃げ、腕を広げて止まる
- 壁・水面・水草の茂みにはぶつからず、手前すぎ・奥すぎにも行かない
- 向きを変えるときは、体をゆっくり回す（その場でくるっと回らない）

## 4. 代替案の比較

| 案 | 内容 | 見た目 | 動き | 手間・保守 | 評価 |
|---|---|---|---|---|---|
| A | Blender から形・骨組み・4つの動きを1つのファイル（.glb）に書き出し、水槽で読み込む。半透明の見た目はブラウザ用に作り直す。どこへ泳ぐかは水槽側のプログラムで決める | ○ 近い見た目に作り直す（完全一致はしない） | ◎ 確認済みの動きをそのまま使える | 中。形や動きを Blender で直せば書き出し直すだけ | **採用** |
| B | イカの形と動きを、水槽側のプログラムで一から作り直す（元の魚と同じ作り方） | ○ | × 確認済みの動きを作り直し。調整が二重になる | 大。Blender とブラウザで二重管理 | 棄却 |
| C | Blender でイカを動画・連番画像に書き出し、水槽に貼る | ◎ Blender と同じ | × 向きを変えられない・ポインタに反応できない | 小 | 棄却 |

### 採用理由（案A）
- 前回「イカらしい」と確認をもらった動きを、そのまま水槽で使える（作業が無駄にならない）
- 形・動きの修正は今まで通り Blender 側だけで行い、書き出し直せば水槽に反映される（二重管理にならない）
- 水槽の中で自由に向きを変え、ポインタに反応できる

### 棄却理由
- 案B: 確認済みの動きを作り直すことになり、Blender との二重管理になる
- 案C: 動画の貼り付けなので、水槽の中を自由に泳がせる目的を満たせない

### ブラウザ用の見た目（Blender の見え方に近づける）
| 部位 | Blender の見え方 | ブラウザでの作り方 |
|---|---|---|
| 胴・頭・腕 | 壁を斜めに見通す輪郭が濃い青緑、中央は明るく抜ける | 視線と面の角度で濃さを変える半透明（輪郭ほど濃く・中央ほど透明）。色は焼き込んだ頂点の色 |
| エンペラ | 付け根が濃く、縁へ向かって透明に消える | 書き出した厚みで濃さを決める |
| 眼 | 金色の半透明の球、縁ほど濃い | 輪郭ほど濃い金色の半透明 |
| 内臓 | 黄緑の消化腺などが透けて見える | 色付きの半透明。胴より先に描いて、胴越しに透けて見えるようにする |
| 表面 | 濡れたツヤ | 水槽の照明を映すツヤ |

### 大きさ
- 胴の長さ（ML）を水槽の単位で **1.1**（元の魚の約1.7倍）。触腕の先まで含めると全長約2.5。水槽の幅（16.6）の約15%
- 数値1つで変えられるようにし、画面を見て調整する

### 泳ぐ場所の判断（水槽側）
| 状態 | 使う動き | 内容 |
|---|---|---|
| ホバリング | Hover | 4〜10秒その場に浮く。ゆっくり少し向きを変える |
| 移動 | SwimForward | 開けた水中（`OPEN` の範囲・水草の茂みの上）から次の目的地を選び、頭を先にして約0.8 ML/秒で進む。目的地の方へゆっくり向きを変える |
| 後退 | SwimBackward | ときどき（目的地がすぐ後ろのとき）尾を先にして少し下がる |
| 逃げる | Jet | ポインタが速く近づいたら、ポインタと反対側へ尾を先にして急発進。動きのデータと同じ速さの変化（最高 7 ML/秒 → 水の抵抗で減速）で移動し、終わったらホバリングへ |
- 動きの切り替えは0.4〜0.6秒かけてなめらかにつなぐ
- 移動の速さは、動きのデータの羽ばたきと合う値にする（足が滑って見えないように）
- 壁・水面・床（`BOUNDS`）と水草の茂み（`plants.thickets`）に近づくと、目的地を選び直す／速度を落とす
- 元の魚（`?fish=1`）を表示したときも、イカはそのまま泳ぐ（魚との関わりは今回の対象外）

## 6. 副作用・リスク

| リスク | 程度 | 対策 |
|---|---|---|
| ブラウザでは Blender と全く同じ半透明にはならない | 中 | 同じ角度の Blender 静止画と水槽のスクリーンショットを並べて比較し、調整する。差が残る点は報告する |
| `main.js` 300行目で位置の自動更新が止められ、イカの骨が動かない | 高 | イカを追加した後、イカ（と骨）だけ自動更新を戻す。骨が実際に動いていることをブラウザで数値確認 |
| 半透明の部品が重なって描画順が乱れ、ちらつく | 中 | 内臓→胴→エンペラ→腕の順を固定し、奥行きの書き込みを調整。複数角度で確認 |
| 描画が重くなり、水槽のコマ数が落ちる | 中 | 書き出し時に部品をまとめる。`?diagnostics=1` で追加前後の描画回数・コマ数を比較 |
| 読み込み部品の版が水槽と違って動かない | 低 | 水槽と同じ 0.180 の公式部品を使う |
| 水槽の他の機能（エサ・一時停止・画質切替・壁紙）が壊れる | 低 | 既存の自動テスト（`npm test`）と文法チェック（`npm run check`）を全部通す。一時停止中はイカも止まることを確認 |
| イカのファイルが読めないとき | 低 | 水槽のエラー表示（既存の `reportSceneError`）に出して止める（黙って隠さない） |

## 7. 検証方法
1. 書き出したファイルに 4つの動き・骨98本・全部位が入っていることを自動確認
2. ブラウザ（`http://127.0.0.1:8080/scenes/riverscape/`）でイカが泳ぐことをスクリーンショットで確認。コンソールエラー0件
3. 見た目: Blender の静止画と水槽のスクリーンショットを比較
4. 動き: ホバリング→移動→ホバリング、後退、ポインタでジェット噴射、が起きることを確認
5. 範囲: 自動テストで、長時間（シミュレーション上10分）泳がせても範囲外・茂みの中に入らないこと
6. 既存機能: `npm test` / `npm run check` 全合格、一時停止・エサ・画質切替が今まで通り
7. 貼り付けるだけの確認スニペットをお渡しし、画面で「イカらしいか」を判断してもらう
